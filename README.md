# SRAMS - Student Record and Academic Management System

A Python web application (Streamlit + SQLite) that centralises student records, courses,
attendance, marks, grades, analytics, notifications and reports, with role-based dashboards
for **Admin**, **Faculty** and **Student**.

## Quick start (Mac / Linux)

```bash
cd Student_Academic_Management_System
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt

python seed_data.py --reset     # creates demo data + trains the ML model (about 10 s)
streamlit run app.py            # opens http://localhost:8501
```

On Windows use `venv\Scripts\activate` instead of `source venv/bin/activate`.

Without running `seed_data.py` the app starts with an empty database and a single account:
`admin` / `Admin@12345` (you are forced to choose a new password at first login).

### Demo logins (created by `seed_data.py`; sample data only)

| Role    | Username                       | Password       |
|---------|--------------------------------|----------------|
| Admin   | `admin`                        | `Admin@12345`  |
| Faculty | `fac001` ... `fac005`          | `Faculty@123`  |
| Student | `aiml2026001`, `aiml2026002`...| `Student@123`  |

The 30 demo students, their attendance and marks are **randomly generated**. Delete the
database (`python seed_data.py --reset` rebuilds it) before using the app with real data, and
change every password.

## What is included

| Module | Highlights |
|---|---|
| Authentication | bcrypt password hashing, password policy, lock-out after 5 failed logins, forced password change on first login, admin password reset, activate/deactivate accounts, role-based page access |
| Student management | Unique IDs (`AIML2026001`), validation, search by name/ID, filters (department/semester/division), update, delete with all related records, auto-created student login |
| Course management | Courses, credits, theory-only vs practical courses, assign faculty, enrol students (single or whole semester cohort) |
| Attendance | Faculty marks Present/Absent per lecture; saving again corrects instead of duplicating (also enforced by a database UNIQUE constraint); automatic %; below-75% alerts; "lectures needed to reach threshold"; monthly report; charts |
| Marks and grades | Internal / Practical / External with configurable maximums; configurable grade scale; automatic total, %, grade, SGPA; result sheet PDF |
| Analytics | Attendance and marks by subject, pass/fail, semester trend, top students |
| Notifications | Low-attendance alerts (max once a week per course), announcements, result-publication notices, optional email via SMTP |
| Reports | Student profile, attendance, marks, course, department and semester result sheet as **PDF, Excel and CSV** |
| AI (phase 2) | Random Forest at-risk prediction, rule-based recommendation engine, student chatbot |

Pages by role: **Admin** - all pages. **Faculty** - Dashboard, Attendance, Marks, Analytics,
AI Analytics, Notifications, Reports (only for the courses assigned to them).
**Student** - Dashboard, Profile, Attendance, Results, Academic Assistant, Notifications, Reports (own records only).

## Running the tests

```bash
pytest -q
```

The suite covers password hashing and policy, lock-out, role access, student CRUD and
validation, duplicate prevention, attendance and grade calculations (including edge cases),
mark limits, SGPA, the ML model, chatbot privacy, and PDF/Excel generation. Each test uses its own temporary database.

## The AI features - please read

* **Prediction model.** `ai/train_model.py` trains a Random Forest on the `historical_records`
  table (attendance %, internal %, previous semester %, assignment completion %, practical %
  -> Good / Average / At Risk) and reports accuracy on a held-out 20 % split.
  **The demo history is synthetic**, generated by `seed_data.py` from a rule plus noise, so the
  demo accuracy only shows the pipeline works. For real use, load your institution's past
  cohort outcomes into `historical_records` and run `python -m ai.train_model` (or press
  *Retrain* on the AI Analytics page). Treat predictions as decision support, not as a verdict
  on a student.
* **Missing inputs.** A student needs recorded attendance and internal marks to get a
  prediction; other missing inputs are replaced by the training median.
* **Chatbot.** Rule-based keyword matching (no external AI service). It always reads the records of the
  logged-in student; the question text is never used to choose whose data to read, and
  questions naming another student's ID are refused.
* The trained model file (`ai/model.joblib`) is loaded with joblib/pickle. Only load model files
  created by your own server.

## Configuration

* **Grade scale, maximum marks, attendance threshold** are stored in the `settings` table
  (`grade_scale`, `max_marks`, `attendance_threshold`). Maximum marks can be edited on the
  *Marks & Results -> Grading rules* page; edit the others with SQL or `database.db.set_setting`.
  Defaults: Internal 30, Practical 20, External 50; threshold 75 %; pass = grade other than F (40 %).
* **Email (optional)** - set environment variables before starting: `SRAMS_SMTP_HOST`,
  `SRAMS_SMTP_PORT` (587), `SRAMS_SMTP_USER`, `SRAMS_SMTP_PASSWORD`, `SRAMS_SMTP_FROM`. If unset, only in-app notifications are created.
* `SRAMS_DB` - path of the SQLite file. `SRAMS_AUTO_SEED=1` - load demo data on first start.

## Security notes

* Passwords are hashed with bcrypt (PBKDF2 fallback if bcrypt is not installed); never stored in plain text.
* There is no public sign-up: only an admin can create accounts. Temporary passwords are shown once and must be changed at first login.
* Role checks happen in the router *and* inside each module; students only ever query their own `ref_id`.
* All SQL uses parameter binding. Foreign keys, UNIQUE and CHECK constraints protect data integrity.
* Before real use: run behind HTTPS, review the password/lock-out policy, and back up the database.

## Deployment

* **Streamlit Community Cloud** - push to GitHub, create the app with `app.py` as the entry
  point. Its file system is not durable: SQLite data can be lost on restart, so use it for demos
  only (set `SRAMS_AUTO_SEED=1` to get demo data).
* **Production** - host on a server/VM (e.g. AWS EC2) with a persistent disk, or move to
  PostgreSQL. `database/db.py` is the only module that opens connections, so it is the place to swap the database.

## Known limitations

* The UI was developed and checked against a stand-in for Streamlit; the business logic is covered by
  the automated tests. Run the app and click through each role before submission.
* Designed for hundreds of students on SQLite. Analytics recompute on each page load (no caching).
* SQLAlchemy is not used (plain `sqlite3` keeps the code smaller); the schema is portable if you want to adopt it.
* No bulk CSV import, timetable, fee or exam-hall modules.
